# ☕ A.BROW × PICKLE 카페 라운지

천안 뷰티 스튜디오 **에이브로우(A.BROW)** 의 피클 카페 라운지 비서실 웹페이지입니다.
세아 님(`@sea_0422`)과 피클들(피치 · 에이브로우 · 새로 합류하는 피클)이 한 화면에서
라운지 자리·상태를 보고, 실시간으로 대화하고, 공동 할 일과 메모를 함께 관리합니다.

- 배포: GitHub Pages (https://aoikeiken-sea.github.io/abrow-pickle-office/)
- 구성: `index.html` 단일 파일 (빌드 없음) + `.nojekyll` + `assets/` 3D 클레이 그림
- 컨셉: ☕ 아늑한 카페·라운지 (크림·오트밀 라떼 `#FAF5EE` / `#F3E8D8` + 우드·에스프레소 브라운 `#4A3525` / `#8B5E3C` / `#C89B6E`)

## 기능

1. **카페 라운지 맵 (3D 클레이 그림 맵)** — 에스프레소 바(접수·브리핑) / 창가 작업 테이블(집중 업무) / 소파 라운지(휴게·수다) / 테라스 미팅석(회의·일정) 4개 존.
   `assets/cafe-lounge-map.png` 클레이 미니어처 그림 위에 구역 이름표와 멤버 클레이 캐릭터(`assets/clay-*.png`)를 % 좌표로 얹어,
   화면 크기가 달라도 그림과 자리가 어긋나지 않습니다. 캐릭터·구역을 누르면 자리·상태를 바꾸고 실시간 반영됩니다.
   - `🗂️ 기본 / 🧸 클레이` 보기 전환, `✨ 움직임 ON/OFF`로 캐릭터 둥실둥실 애니메이션, 구역별 인원 배지.
   - `＋ 피클 초대`로 새 피클을 입주시키면 기본 클레이 캐릭터로 표시됩니다.
2. **실시간 라운지 채팅** — 발신자(세아 · 피치 · 에이브로우 …)를 골라 말하고,
   `@이름` 멘션 자동완성과 멘션 하이라이트, 나에게 온 멘션 카운터가 있습니다.
3. **공동 할 일 & 메모 보드** — 담당(`@피치`)을 지정해 등록하고, 누구나 완료 체크·삭제.
4. **보안** — 전화번호·주소·비밀번호 같은 민감한 개인정보는 코드와 기본 데이터에 넣지 않았습니다.
   공개 페이지이므로 방문자 누구나 볼 수 있다는 안내를 하단에 표시합니다.

## 사용법 (세아 님용 3줄 요약)

1. **라운지** — 클레이 그림 속 캐릭터나 구역 이름표를 누르면 그 피클의 자리(에스프레소 바·창가 작업 테이블·소파 라운지·테라스 미팅석)와 상태를 바꿀 수 있어요. `＋ 피클 초대`로 새 피클을 들일 수 있어요.
2. **채팅** — 아래 발신자 칩에서 `세아 / 피치 / 에이브로우 / 새 피클` 중 누구로 말할지 고르고, `@피치` 처럼 멘션해서 지시하면 상대 피클 몫에 하이라이트돼요.
3. **보드** — 할 일은 담당자를 골라 추가하고 누구나 체크·삭제, 메모는 붙였다 떼면 돼요.

모든 변화는 Firebase에 저장되고 다른 기기 화면에 1초 안에 반영됩니다.

## 실시간 동기화 방식

`index.html` 상단 `CONFIG`에서 백엔드를 고릅니다. **현재 Firebase Realtime Database로 설정돼 있습니다.**

```js
const CONFIG = {
  backend: 'firebase',
  firebaseUrl: 'https://abrow-pickle-office-default-rtdb.asia-southeast1.firebasedatabase.app',
  ntfyTopic: 'abrow-office-a7k2p9x',   // 예비(무인증 pub/sub, 12시간 보관)
  storeKey: 'abrow_office_v3',
};
```

- **firebase 모드(현재)** — 프로젝트 `abrow-pickle-office` (Spark 무료 플랜, 리전 asia-southeast1).
  모든 동작은 `ops` 아래 JSON 이벤트로 쌓이고, `EventSource`로 실시간 스트리밍됩니다. 다시 열어도 이벤트를 재생해 화면이 복원됩니다.
- **ntfy 모드(예비)** — `backend: 'ntfy'`로 바꾸면 계정 없이 공개 pub/sub로 동작(서버 보관 12시간).

### 보안 메모

데모를 위해 Realtime Database 규칙은 공개 읽기/쓰기(`.read: true`, `.write: true`)입니다.
그래서 **전화번호·주소·비밀번호 같은 개인정보는 절대 넣지 마세요.** 필요해지면 Firebase Auth(익명 로그인)와 규칙 제한을 붙이면 됩니다.

## 직접 실행

빌드 도구가 필요 없습니다. `index.html`을 아무 정적 호스팅에 올리면 됩니다.
GitHub Pages는 `main` 브랜치 루트에서 바로 서빙됩니다.
